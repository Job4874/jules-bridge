## 2025-01-20 - Fix set-state-in-effect warning
**Learning:** Calling `setState` directly inside a `useEffect` triggers additional unnecessary re-renders in React, which hurts performance and is flagged by linters (`react(set-state-in-effect)`). In `App.jsx`, `selectedWorkerKey` and `selectedCollisionKey` were being updated in `useEffect`s to fall back to the first available item if the currently selected key became invalid.
**Action:** Instead of managing these keys purely in state and correcting them asynchronously in effects, we derived the validity of the selected keys during the render cycle. If the statefully selected key is no longer in the list, we compute the fallback (e.g., the first item) inline. This removes the need for effects, eliminates the cascading re-render, and satisfies the linter rules without breaking the functionality.
